# Todoリストアプリ 完全仕様書

## 1. プロダクト概要

### 1.1 目的
- 個人のタスク管理を効率化するシンプルなWebアプリケーション
- 直感的な操作でタスクの追加・編集・削除・完了管理を実現
- テスト用途として、基本的なCRUD操作とUI/UX設計の検証を目的とする

### 1.2 ターゲットユーザー
- **プライマリターゲット**: 個人でタスク管理を行いたい一般ユーザー
- **セカンダリターゲット**: 開発者・テスター（機能検証用途）
- **年齢層**: 18-65歳
- **技術レベル**: ITリテラシー基礎レベル以上

### 1.3 価値提案
- **シンプルさ**: 複雑な機能を排除した直感的なインターフェース
- **即座の利用開始**: アカウント登録不要でブラウザ上ですぐに利用可能
- **基本機能の完全性**: タスク管理に必要な最小限の機能を確実に提供
- **レスポンシブ対応**: PC・タブレット・スマートフォンで利用可能

## 3. 画面一覧

### 3.1 メイン画面（Todo List画面）
- **役割**: アプリケーションのメイン機能を集約した単一画面
- **構成要素**:
  - ヘッダー部: アプリタイトル「Todo List」
  - 入力部: 新規タスク入力フィールド + 追加ボタン
  - フィルタ部: 表示切り替えボタン（全て/未完了/完了済み）
  - タスクリスト部: タスク一覧表示エリア
  - フッター部: タスク件数表示、一括削除ボタン

### 3.2 タスク項目コンポーネント
- **役割**: 個別タスクの表示と操作
- **構成要素**:
  - チェックボックス: 完了/未完了切り替え
  - タスク名表示: テキスト表示（編集モード時は入力フィールド）
  - 編集ボタン: タスク名編集開始
  - 削除ボタン: タスク削除

### 3.3 確認ダイアログ
- **役割**: 削除操作の確認
- **構成要素**:
  - 確認メッセージ
  - キャンセルボタン
  - 削除実行ボタン

### 3.4 エラー表示
- **役割**: バリデーションエラーやシステムエラーの表示
- **構成要素**:
  - エラーメッセージ表示エリア
  - 自動非表示機能（3秒後）

## 4. データモデル案

### 4.1 Todoアイテムモデル

```typescript
interface TodoItem {
  id: string;              // 一意識別子（UUID v4）
  title: string;           // タスク名（1-200文字）
  completed: boolean;      // 完了状態（true: 完了, false: 未完了）
  createdAt: Date;        // 作成日時（ISO 8601形式）
  updatedAt: Date;        // 更新日時（ISO 8601形式）
  order: number;          // 表示順序（0から開始の整数）
}
```

### 4.2 アプリケーション状態モデル

```typescript
interface AppState {
  todos: TodoItem[];           // Todoアイテム配列
  filter: FilterType;          // 現在のフィルタ状態
  isLoading: boolean;         // ローディング状態
  error: string | null;       // エラーメッセージ
}

type FilterType = 'all' | 'active' | 'completed';
```

### 4.3 ローカルストレージスキーマ

```json
{
  "todoApp": {
    "todos": [
      {
        "id": "uuid-string",
        "title": "サンプルタスク",
        "completed": false,
        "createdAt": "2024-01-01T00:00:00.000Z",
        "updatedAt": "2024-01-01T00:00:00.000Z",
        "order": 0
      }
    ],
    "settings": {
      "lastFilter": "all"
    }
  }
}
```
